# 性能架构与优化记录(PERF)

> 2026-10-24/25 十四轮性能优化(实测驱动;多会话推送规则见仓库根 COLLABORATION.md)的机制沉淀。**改渲染管线/列车绘制前必读** ——
> 下列机制互相咬合,单独改一处很容易破坏其它轮次的假设。

## 实测基线(2026-10-25,凌晨/正午拨钟,MessageChannel 基准)

| 场景 | 优化前 | 优化后 |
|---|---|---|
| 全国(z3.4)空闲常驻 | 20fps 全量重绘 + 每帧 8.5ms 扫描 | 4fps 渲染 + 每分钟 1 次扫描 |
| 全国拖动 | 每帧重建(8.5ms,60fps 下占半核) | 纯平移免重建(重建 1/15) |
| 全国缩放 | 每帧 8.5ms 扫描 | 0 次(缓存命中) |
| 城市(z14)空闲·正午 | 每帧 4.32ms(9402 顶点全写) | 1.69ms(视口外免写) |
| 城市·凌晨 | 每帧 3.45ms(网格全扫) | 0.01ms(扫描缓存) |
| 启动 | ~90MB + 3 次大 JSON 冻结 | 懒加载省 65MB + HTTP/IDB 5min 新鲜度 |
| 拾取(悬停/点击) | 每车一次 map.project | 局部雅可比(千倍加速) |

## 渲染管线(tick → updateTrains → trains-gl)

### 1. 重建率自适应(帧步长)

```
纯平移(z<5,zoom 未变,无渐变/跟随/拖动)   → 免重建,仅 4fps 补帧(panOnly)
淡入淡出进行中(anyFading)                → 15fps(保 260ms 渐变平滑)
静态:z<5 → 4fps / z5-8 → 10fps / z≥8 → 30fps
交互(viewDirty+zoomMoved)/跟随/拖动时间轴 → 全帧
```

**不变量**:列车顶点是世界坐标 + 屏幕尺寸按 zoom 烘焙(`a_corner` × L/W)——
纯平移/旋转只由相机矩阵变换;**zoom 变化必须重建**(尺寸/等级门依赖 zoom)。
跳过帧的渲染输出与上一帧逐像素相同,故 `triggerRepaint` 仅在重建帧调度
(交互/瓦片加载帧 MapLibre 自行渲染)。

### 1b. 段内线性快径(_fk,十九轮/21a 修复)

trainPosition 快径缓存子段几何(kLo/kSpan/c0/dx),**仅在 target=frac×len 落在
[kLo, kLo+kSpan] 内时才可用** —— 时间窗 [m0,m1] 守卫不够:M 在同一区间内跨过
子段边界后,沿旧子段弦外推 = 线路外数公里,直到下一站重建才跳回(乱飞+抽搐;
倍速/拖滑块放大)。21a 轮补上域检查,越界回退全量重解。实测口径(全班次
M=410-850 步长 20 扫描):修复前 21 个采样点 1-7 辆/点(日豊本線 31 次、
奥羽/仙山/北陸新幹線含 1e18 无几何哨兵),修复后 0。

### 2. 阶段 1 扫描缓存(scanStamp 系列)

eligible 集合只取决于 `[整数分钟, 等级门, 视口矩形(z≥5), 纯线模式, 数据档]`。
缓存命中时跳过 8.2ms 全量扫描(86,085 班次)。**5s TTL 兜底**班次起终点分钟边界
(出现/消失最多迟 5s)。缓存帧 `fadeStamp` 不递增(`_ok/_fm` 语义依赖此约定);
阶段 3 的 M2 每帧重算(缓存的 `t._M2` 是扫描期旧值,禁止用于插值)。
跟随/详情强制环在缓存外**每帧**执行(≤2 辆)。

### 3. 视口外免写(阶段 3,双层矩形)

bbox 级 eligible 含大量「线路穿过视口但车在远处」的班次(正午 z14 東京实测
合格 9402 顶点 ≈ 屏内 ~500 的 19 倍)。两层矩形各司其职:
- **扫描矩形**(vm 缓冲,高 zoom ~14km):阶段 1 用,保证班次 bbox 命中;
- **写矩形**(wRect,视锥 + 64px 车身/光晕余量):阶段 3 解算位置后判定,
  矩形外跳过顶点写出/颜色/图标/M3D 接管(十四轮收紧后实测顶点 5754→486,-92%)。

班次仍在 fadeList(alpha 保持),驶入视锥即恢复写出(屏缘出现,无淡入突变)。
跟随/flyTo 相机跳变由逐帧判定天然覆盖(检查对当前相机无状态)。
z<5 无 vp → wRect=null 不裁切(全国所有在途班次都可能入屏)。
阶段 3 的 M2 每帧重算(缓存的 `t._M2` 是扫描期旧值,禁止用于插值)。
跟随/详情强制环在缓存外**每帧**执行(≤2 辆)。

### 4. 淡入淡出

`anyFading`(阶段 2 实时标记,含新入列班次)驱动升帧;alpha 按真实 dt 推进,
帧率无关。**FADE_MS=260 内改动画时长需同步检查 anyFading 升帧档(4 → 15fps)。**

### 5. 拾取(局部雅可比)

一次 pick 仅 4 次投影变换标定局部线性系数,列车用经纬度差×系数求屏幕距。
globe 模式拾取半径(10-14px)内误差 ~0.2px。**勿改回逐车 map.project**
(全国视图 9000 车/次 × 16 次/s,与渲染争抢主线程)。

## 加载与缓存

- **懒加载**:ORM 股道 44MB(`bindLazyHeavyData`,z≥11.5 延迟 3s 触发/开关)、
  站房三件套 14MB(同触发)、`platform_map.json` 3.3MB(dataReady 后 4s)。
  触发回调自续重试(深链冷缓存场景),多条链幂等。
- **HTTP 缓存**(build_static_assets.py `_headers`):数据 JSON/GeoJSON/JS 5min
  浏览器缓存;徽章图集 `sha256/*.webp` 内容寻址 → 1y immutable。
- **IDB 新鲜度**:`fetchJSONWithCache` 的 `t0` 与服务端 5min 对齐 —— 窗口内零网络
  零解析;**勿删除**(否则浏览器缓存 200 走全量重解析,反而劣化)。
- **DATA_VERSION 必须随任何数据内容变更递增**(2026-10-25 乱飞事故根因):索引缓存
  (`idx|<版本>`)与数据文件缓存(`<版本>|<url>`)都以它为键。周更流水线(refresh.yml)
  刷新 trains/station_map/tokkyu 却不递增 → 10-18 起 extra_stations 5→9 等变更
  落不进老访客的缓存,旧索引×新时刻表错配出「线路外乱飞」(如 長崎電気軌道 #10782
  21073km/h)。refresh.yml 已改为自动递增;另有已知缺陷:无 ETag/Last-Modified 的
  数据条目永不重验证(`else return cached.j`)——递增版本换键可中和,改语义需评估
  离线可用性,暂不动。
- 图集:default 启动即载(加载拼图),vector/cute 首次切换懒加载(`ensureAtlas`)。
- Clarity 延后 dataReady+4s;maplibre CSS 非阻塞(preload+onload);line_icons.js defer。

## 设备分层

`__PERF_LOW`(软渲染/低端):全套降载 + 4fps 起步。
`__PERF_MID`(桌面 3-4 核):pixelRatio ≤1.5 + crossSourceCollisions:false +
prefetchZoomDelta 1。高端:无任何画质牺牲。

## 二十二轮(2026-10-25):停站列车图标原地高速自转 —— 前瞻方位角 + 截取端点校验收紧

**症状(偶发)**:列车停在车站时图标原地高速自转/鞭打。台架复现:銚子電気鉄道線
tid 6adc9fd5…c76c @ M=371 笠上黒生,16× 回放下朝向在 -90°/124°/162° 间连续跳变。

**机制(两层叠加)**:
1. `segSubPath` 把到站坐标投影到 2.0km 外的邻段长段上反向截取(端点校验阈值 3km 放行)
   → 笠上黒生→本銚子 区间路径整段反向,列车沿来路折返爬行;
2. 截取折线含 2-4m 近重复点,子段弦长与坐标量化(1e-5°≈1.1m)同量级
   → 逐帧 `atan2` 方位角成噪声 = 原地高速自转。

**修复**:
- 运行段方位角改为沿 cum 前瞻取点定向(`target + min(30m, len*0.25)`),跨过噪声子段;
  快径 `_fk.brg` 经 `cbrg` 自动继承,无额外分支;
- `segSubPath` 端点校验 3km → 1.5km,失配截取交还 `officialPath`(每区间官方折线)接管。

**验证(台架全量)**:
- 全天每 45 分钟 × 全部 94,482 班次:真实脱轨(>3km)0 起;
- ±0.5min 到发窗 16× 逐帧朝向直方图:翻转≥3 的窗口 290/1,432,529(0.02%,抽查均为真实
  街角/弯道阶梯转向;修复前头部案例为 6 次 ±180° 随机鞭打);
- 新旧位置抽样对比:~1-2% 运行班次区间路径变更(3km→1.5km 校验收紧所致),
  抽查全部落在 officialPath 官方几何(広電本線/豊肥本線/東京モノレール等)。

## 二十三轮(2026-10-26):同类普查 —— 整区间反向行驶 / 错段误用 / 钳制串线 / 停站错向 五合一

**普查方法**:对全部 94,482 班次逐区间采样 15%/50%/85% 进度,检测「距下一站单调远离」
(反向行驶签名)、停站朝向 vs 发车朝向跳变、真实脱轨(>3km)、朝向与移动方向背离。

**发现的家族与修复**:
1. **整区间反向行驶**(宝殿→曽根、香取→佐原 等,~2700 起/天):segIndex 存在键 A|B 但坐标
   实为 B→A 的反向注册段,主路径无方向对齐 → 列车整区间倒行、终点停在出发站。
   修复:`orientSeg` 按双站坐标定向,必要时换用惰性反向孪生(`revSegEntry`,cum 反演)。
2. **键名与几何不符的错段**(氷川台|平和台 实为千川→池袋段 286 起、鴫野|放出 实为北向段 67 起):
   pickSeg 无条件信任候选 → 修复:orientSeg 双端校验(任一端距两站均 >1.5km 即弃用),
   落空后由 officialPath 官方几何接管。
3. **邻段投影截取遮蔽官方几何**(七隈線 六本松→桜坂 被 別所|六本松 段截反):市区短站距下
   错误邻段端点可同时落入容差 → 修复:fallback 链序对调,officialPath 权威优先。
4. **钳制把直通车拽上名义线路**(相鉄直通 海老名→大和 名义東海道本線,被整段拽到 10km 外
   = 「串线」家族):修复:站锚定路径(首尾≤2.5km 落在 cA/cB)跳过钳制,只对 BFS/桥接等
   无锚路径保留钳制;fb 终点校验(>2.5km 弃用落骨架)兜底同名站错配。
5. **停站错向+发车跳变**(新大阪→法隆寺 111°、下今市→東武WS 115°,~230 起/天):停站朝向
   取整段弦(大弯段平均方向)与出站切线差 110°+ → 修复:停站朝向前瞻化(~60m)。

**认证**(台架,问题家族密集的前 32k 班次全扫 + 抽查):
- 反向行驶(折返签名):**0 起**(修复前同范围 369+);七案回归(宝殿|曽根/香取|佐原/六本松|桜坂/
  氷川台|平和台/鴫野|放出/有楽町|豊洲/海老名|大和)全部正常抵近下一站;
- 停站→发车朝向跳变(>109°):12k 班次仅 3 起(修复前同范围 ~30,残余为真实折返/急弯);
- 真实脱轨(>3km,M=585/1000 全量):0 起。

## 二十三轮(2026-10-26):接入 jr-delay 实时列车延误

## 二十三轮.f(2026-10-26):修复描边环两大问题 —— 图标串格 + 环不可见

**串格根因(用户报告:缩放时图标混入其他列车的图标碎片)**:描边环分支被插在图标
早退分支之后 —— 图标模式的环四边形(uvIdx≥0)先撞上图标渲染分支,被当成放大的图标
整体绘制:uv01 超出 [0,1] 约 ±18%,采样越过图集 cell 的 padding,把**相邻格子其他
列车的图标**画在延误车周围(= 串格),而描边环分支从未执行(= 看不到高光)。
**修复**:环分支移到 main() 最前(先于图标早退),环四边形不再进入图标路径。

**环在低倍率消失**:环宽恒定 ~2.2 屏幕像素,低倍率图标仅 ~15px 时 1 图集纹素≈3px,
邻域采样落在同一纹素内(s≈ac)环淡出。补下限:采样半径取 max(屏幕 2.2px, 0.9 纹素),
低倍率下环仍有 ≥1.4 纹素(~1.5px)宽度。

台架:顶点完整性(四边形 6 顶点属性一致 0 错位)、z6↔z15 逐级缩放压力零异常、
非橙线路目标 dly 应用/清除正常、模块与着色器零错误。
